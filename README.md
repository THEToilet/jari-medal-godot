# じゃりメダル ビル解体（プロトタイプ）

Godot 4.6以上 / GL Compatibility / 1920×1080

## ブラウザ版（スマホでも遊べる）
- 2D版：https://thetoilet.github.io/jari-medal-godot/
- 仮想筐体（3D）：https://thetoilet.github.io/jari-medal-godot/virtual/

main ブランチに push すると、GitHub Actions が Web 版を書き出して GitHub Pages に公開する（`.github/workflows/pages.yml`）。
スマホでは右上の「メダル投入」ボタンでメダルを入れ、画面タップがボタンの代わり。メダルが尽きたら投入ボタンで自動補充される。

## 仮想筐体（3D）
`virtual/virtual_cabinet.tscn` は、ゲーム（`scenes/main.tscn`）を3Dの筐体の画面に映して遊ぶシーン。GitHub Pages では `/virtual/` に置く（ルートは今までどおり2D）。書き出し設定「Web Virtual」（カスタム機能 `virtual_cabinet` → `run/main_scene.virtual_cabinet`）で書き出す。PCの `play.bat` や実機は2Dのまま。

- Pages：`pages.yml` が main の2Dをルートに、仮想筐体を `/virtual/` に書き出す（`VIRTUAL_BRANCH` にブランチ名を入れるとそのブランチから作る）
- 画面はブラウン管風のシェーダー（`virtual/crt_screen.gdshader`：ふくらみ・走査線・RGBの縦じま・色ずれ・にじみ・周辺減光）。強さは uniform で調整

- ゲームは SubViewport の中で動かしていて、筐体のボタン → `tap`、投入口 → `coin` を流し込むだけ。ゲーム側には `is_in_play()` を足したのと、筐体の画面の中ではスマホ用の投入ボタンを出さないようにした以外、手を入れていない
- 舞台は「人のいないショッピングモールの角のゲームコーナー」：蛍光灯、リノリウムの床（`virtual/linoleum.gdshader`）、うしろの壁、両隣にも同じ筐体（画面は止まった絵）
- カメラは固定（画面とボタンが近くに見える位置。`CAMERA_OFFSET` で調整）
- ゲームの `finished(払い出し枚数)` を受けて LED を点滅させる

| 操作 | 仮想筐体 |
|---|---|
| メダル投入 | 右上の「メダル」ボタン、または C |
| ボタン | ボタンが乗っている板（かボタン）をクリック/タップ、または Space / Enter |

筐体モデル（`virtual/jari_cabinet.glb`）は `tools/cabinet/build_cabinet.py` で生成している（numpy のみ）。形や色を変えるときはそちらを直して `python3 tools/cabinet/build_cabinet.py` を実行する。詳しくは `tools/cabinet/README.md`。

## 起動
- `play.bat` … ゲームを起動
- `edit.bat` … Godotエディタで開く

初回は Godot の実行ファイル（Godot_v4.x_win64.exe）を自動で探し、見つかった場所を `godot_path.txt` に保存する。
見つからない場合はウィンドウに exe をドラッグ＆ドロップすればOK。
起動のたびに素材のインポートを走らせる（新しい画像を追加しても読み込まれる）。ゲームのログは `godot.log` に出る。場所を変えたら `godot_path.txt` を消すか書き換える。
環境変数 `GODOT` に exe のパスを入れておけばそれを最優先で使う。

## 遊び方
画面は筐体に組み込む前提。ボタン・メダル投入口・払い出し口は筐体側にあるので、PCではキーで代用する。

| 操作 | キー |
|---|---|
| メダル投入（1〜5枚＝爆弾の数） | C |
| 決定・連打・起爆（ボタンは1個） | Space ／ Enter ／ 左クリック |
| メダル+50（デバッグ） | F2 |

### デモプレイ（アトラクト）
- 待機画面のまま **12秒**（`DEMO_AFTER`）なにもしないと、自動で1プレイ見せる。左上に「デモプレイ」の札が出る
- 中身：クレーンでダイナマイトを3つ置く → 払い出し8枚以上のビルを選ぶ → 連打 → 起爆 → 必ず成功 → リザルト
- デモ中はメダルを減らさず、払い出しもしない（CREDIT は 0 のまま）
- デモ中にボタンを押すと待機画面へ、メダルを入れると本番に戻ってそのメダルを1枚目として受け付ける（画面はふわっと溶けて切り替わる）
- 終わるとタイトル表示の待機画面に戻り、12秒後にまたデモ…を繰り返す

流れ：メダル投入（入れるほど画面下にダイナマイトが並ぶ）→ ランダムな並びで流れてくるビルを、中央に来たところでボタンで選択 → 5秒間連打（作業員が発電機を回して、中央のスイッチに電気を溜める） → 「押せー！」で起爆 → 煽り → 崩壊 or 残る

- `scripts/cabinet.gd` 筐体の共通基底（60秒タイムアウト、残り10秒で警告、時間切れでメダル回収）

- `scripts/charge_meter.gd` 起爆器の横の「電気の溜まり」メーター
- `scripts/dynamo.gd` 発電機（現在は非表示。回転の計算だけ流用）
- `scripts/cable.gd` 電線

- `scripts/up_light.gd` ビル選択の、足元から湧き上がる光
- `scripts/insert_sign.gd` 待機中の「メダルをいれてね」看板
- `scripts/medal_tray.gd` 払い出し演出（崩れたビルからメダルが噴き出して画面下へ落ちる。実際の払い出しは筐体の下から）

## 調整ポイント（demolition_cabinet.gd）
- `BUILDINGS` 払い出し・物置の固定確率・演出テンポ
- `NUM_H` 払い出し数字画像の大きさ（枚数ごと）
- `RTP` 払い出し率（0.9）、`MASH_MAX_BONUS` 連打ボーナス上限（×1.1）、`POWER_PER_TAP`
- `PATTERNS` 煽りパターンの出現比率
- `RESULT_TIME` リザルト画面の最低表示時間（ランク別）
- インスペクタ `slot_time` 1棟ぶん進む時間（1.0秒）、`dwell_time` 中央で止まる時間（0.45秒）、`scroll_curve` 速度カーブ（sin / tan）、`linger` tanカーブの粘り具合
- `assets/num/<枚数>.png` 払い出し数字の画像（ビルの右下に表示）。無ければ文字で表示
- インスペクタの「演出の尺」→ `time_scale` で煽り全体を一括短縮

抽選結果は出力パネルに `[抽選] …` として表示される（調整用）。

## 確率とペイアウト率

### 崩れる確率の決め方
```
確率 ＝ RTP ÷（払い出し × AVG_MASH）× 入れた枚数 ×（1 ＋ MASH_MAX_BONUS × 連打パワー）
     ＝ 0.9 ÷（払い出し × 1.05）× 入れた枚数 ×（1 ＋ 0.1 × 連打パワー）
```
- 上限 95%。ものおきだけは固定 98%
- 連打パワー：1回押すごとに +0.03（`POWER_PER_TAP`）、上限 1.0（5秒で34回）。確率は最大 ×1.1。押した回数がそのまま効く（起爆器の4段階の光は見た目だけ）

### 崩れる確率の表（連打ふつう＝パワー0.6、5秒で20回）
| 建物（払い出し） | 1枚 | 2枚 | 3枚 | 4枚 | 5枚 |
|---|---|---|---|---|---|
| ものおき（1） | 98% | 98% | 98% | 98% | 98% |
| おうち（2） | 45% | 91% | 95% | 95% | 95% |
| アパート（5） | 18% | 36% | 55% | 73% | 91% |
| ざっきょビル（8） | 11% | 23% | 34% | 45% | 57% |
| マンション（10） | 9% | 18% | 27% | 36% | 45% |
| こうそうビル（20） | 4.5% | 9% | 14% | 18% | 23% |
| タワー（30） | 3% | 6% | 9% | 12% | 15% |

### 連打の回数による違い（5枚入れたとき）
| 5秒で押した回数 | 0回 | 10回 | 20回 | 30回 | 34回〜 |
|---|---|---|---|---|---|
| 確率の倍率 | ×1.00 | ×1.03 | ×1.06 | ×1.09 | ×1.10 |
| アパート | 86% | 88% | 91% | 93% | 94% |
| ざっきょビル | 54% | 55% | 57% | 58% | 59% |
| マンション | 43% | 44% | 45% | 47% | 47% |
| こうそうビル | 21% | 22% | 23% | 23% | 24% |
| タワー | 14% | 15% | 15% | 16% | 16% |

ものおき・おうちは5枚の時点で上限なので連打しても変わらない。連打の効果は小さめ（最大1割増し）。もっと効かせたいなら `MASH_MAX_BONUS` を上げ、そのぶん `RTP` を下げて全体を合わせる。

### ペイアウト率（還元率）の出し方
```
ペイアウト率 ＝ 払い出した枚数 ÷ 入れた枚数
1回ぶん     ＝（崩れる確率 × 払い出し枚数）÷ 入れた枚数
```
例：マンション（10枚）に3枚・連打ふつう → 27.3% × 10 ÷ 3 ＝ 約91%

上の式を入れると払い出しと枚数が消えるので、上限に当たらない限り **ペイアウト率は連打だけで決まる**。
- 連打なし：0.9 ÷ 1.05 ＝ 約86%
- 平均（パワー0.5）：約90%（ここに合わせてある）
- 全力：0.9 × 1.1 ÷ 1.05 ＝ 約94%

上限に張り付く安い建物は損になる（仕様）：ものおきに5枚 ＝ 98% × 1 ÷ 5 ＝ 約20%、おうちに3枚 ＝ 95% × 2 ÷ 3 ＝ 約63%。

全体のペイアウト率は、お客さんの選び方しだいなのでシミュレーションで出す（30万回、連打パワーは0.3〜0.9のランダム）。
| 選び方 | ペイアウト率 |
|---|---|
| 8枚以上の建物だけ狙う | 約91% |
| 建物も枚数もランダム | 約78% |

実機では IN（入れた枚数）と OUT（払い出した枚数）を数えておき、OUT ÷ IN で確認する。
